# Smart POS Pro v1.0.0

โปรแกรมขายหน้าร้านแบบ Offline-First (หน้าเว็บไฟล์เดียว) เก็บข้อมูลในเครื่อง และซิงค์ขึ้น Supabase เมื่อออนไลน์
ติดตั้งเป็นแอปบน iPad/มือถือได้ (PWA) โฮสต์ฟรีด้วย GitHub Pages

> **สถานะการทดสอบ:** โค้ดฝั่งแอปผ่านการตรวจ syntax และการอ้างอิงฟังก์ชัน แต่ `supabase/schema.sql`
> (รวมจากสคริปต์เดิมหลายไฟล์) **ยังไม่เคยรันกับ Postgres จริง** — ทดลองบนโปรเจกต์ Supabase ทดสอบก่อนใช้กับร้านจริง

## โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | ตัวแอปทั้งหมด (HTML + CSS + JS) |
| `sw.js` | Service worker ให้เปิดแอปได้ตอนออฟไลน์ |
| `manifest.webmanifest`, `icons/` | ติดตั้งเป็นแอป (Add to Home Screen) |
| `supabase/schema.sql` | สคริปต์ฐานข้อมูลไฟล์เดียว (ตาราง, RLS, Storage, RPC) |
| `supabase/diagnose.sql` | คำสั่งอ่านอย่างเดียว ไว้ตรวจสถานะเมื่อซิงค์/รูปมีปัญหา |
| `.nojekyll` | ให้ GitHub Pages เสิร์ฟไฟล์ตามที่เป็น |

## ติดตั้ง

### 1) Supabase
1. สร้างโปรเจกต์ที่ supabase.com
2. SQL Editor → วางเนื้อหา `supabase/schema.sql` ทั้งไฟล์ → Run (รันซ้ำได้)
3. Authentication → Providers → Email เปิดใช้งาน (ถ้าเปิด *Confirm email* ต้องกดลิงก์ยืนยันในอีเมลก่อนล็อกอินครั้งแรก)
4. Authentication → Sign In / Providers → Password security → เปิด *Prevent use of leaked passwords* (ต้องแพลน Pro ขึ้นไป)
5. Project Settings → API → จด **Project URL** และ **anon public key** (ห้ามใช้ `service_role` ในแอป)

### 2) GitHub Pages
1. สร้าง repo แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (โครงสร้างเดิม)
2. Settings → Pages → Source: *Deploy from a branch* → `main` / `(root)`
3. เปิด `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/` (ต้องเป็น https เพื่อให้ service worker ทำงาน)
4. iPad/iPhone: Safari → แชร์ → *เพิ่มไปยังหน้าจอโฮม*

### 3) เชื่อมแอปกับ Supabase
เปิดแอป → ตั้งค่า → ฐานข้อมูล Supabase → ใส่ Project URL และ anon key → ล็อกอินร้านด้วยอีเมลเจ้าของ
→ ตั้งค่าเจ้าของร้าน (ครั้งแรกเท่านั้น) → กดซิงค์

### ผูกบัญชีเจ้าของร้าน (เมื่อซิงค์สินค้าไม่ได้เพราะสิทธิ์ไม่พอ)
แอปเขียนสินค้า/หมวดหมู่ได้เฉพาะบัญชีที่มีแถวใน `app_users` เป็น OWNER หรือ MANAGER
ถ้าแอปแจ้งว่าสิทธิ์ไม่พอ ให้รัน `supabase/diagnose.sql` ข้อ 1–2 ดูสถานะ แล้วผูกบัญชี (แก้อีเมลก่อนรัน):

```sql
update app_users
set auth_user_id = (select id from auth.users where email = 'อีเมลเจ้าของร้าน@example.com')
where role = 'OWNER';
```

## อัปเดตแอป
แก้ไฟล์ → **เปลี่ยนเลข `VERSION` ใน `sw.js`** → push ขึ้น GitHub → ปิดแล้วเปิดแอปใหม่ 1–2 ครั้ง
(ไม่เปลี่ยนเลขอาจทำให้บางเครื่องยังเห็นหน้ารุ่นเก่า)

## ข้อควรรู้
- **สำรองข้อมูลก่อนเสมอ:** ข้อมูลหลักอยู่ในเครื่องก่อน — ตั้งค่า → ฐานข้อมูล → สำรองข้อมูลเป็นไฟล์ ก่อนอัปเดตหรือล้างเครื่อง
- **CSS:** แอปใช้ CSS ที่เขียนเองแทน Tailwind CDN — ถ้าเพิ่ม class ของ Tailwind ใหม่ในหน้า ต้องเพิ่มกฎใน `<style>` ด้วย
- **ข้อจำกัดที่ยังไม่ได้ทำ:** การห้ามขายต่ำกว่าทุนเช็คที่เครื่องเท่านั้น (ไม่ใช่ที่เซิร์ฟเวอร์);
  เลขบิลอิง timestamp+deviceId ไม่ใช่เลขใบกำกับภาษีรันต่อเนื่อง — ถ้าจดทะเบียน VAT ควรปรึกษาผู้ทำบัญชี
- **anon key** อยู่ในเบราว์เซอร์ได้ตามปกติ เพราะความปลอดภัยอยู่ที่ RLS — แต่ห้ามเผยแพร่ `service_role` key
- รูปสินค้าเก็บใน bucket `product-images` (public, ≤ 5 MB/ไฟล์) เอกสารรับสินค้าใน `delivery-notes` (private)

## แก้ปัญหาเบื้องต้น
| อาการ | ตรวจ |
|---|---|
| ซิงค์สินค้าไม่สำเร็จ | อ่านข้อความ error ที่แอปแสดง (ระบุสาเหตุแล้ว) → `diagnose.sql` ข้อ 1–2 |
| รูปไม่ขึ้นบนเครื่องอื่น | เมนูตรวจสุขภาพข้อมูล → "รูปยังอยู่ในเครื่องเท่านั้น" → กดซิงค์ / `diagnose.sql` ข้อ 4 |
| แอปไม่อัปเดต | เปลี่ยน `VERSION` ใน `sw.js`; หรือลบเว็บไซต์ออกจากหน้าจอโฮมแล้วเพิ่มใหม่ |
