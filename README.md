# Smart POS Pro — แบ่งไฟล์แบบ Plain Script (ไม่ใช้ ES Modules)

## จุดต่างจากเวอร์ชัน ES Modules

เวอร์ชันนี้ **ไม่ใช้** `import`/`export` — ทุกไฟล์เป็น `<script>` ธรรมดา โหลดเรียงกัน
3 ไฟล์ และแชร์ scope ตัวแปร/ฟังก์ชันเดียวกันโดยอัตโนมัติ (พฤติกรรมปกติของ `<script>`
หลายๆ อันในหน้าเดียวกัน) ผลคือ:

- ✅ เปิดไฟล์ `index.html` ตรงๆ แบบ `file://` ได้เลย ไม่ต้องมีเว็บเซิร์ฟเวอร์
- ✅ Deploy ขึ้น Firebase Hosting/โฮสต์ไหนก็ได้แบบไฟล์ static ธรรมดา ไม่มีความซับซ้อนเรื่อง
  CORS/MIME/module resolution เหมือนเวอร์ชัน ES Modules
- ✅ ไฟล์ละ ~1,500-1,700 บรรทัด แก้ง่ายกว่าไฟล์เดียว 4,800 บรรทัด
- ⚠️ ต้องโหลดตามลำดับเสมอ: `part1.js` → `part2.js` → `part3.js` (กำหนดไว้ใน
  `index.html` แล้ว ไม่ต้องแก้อะไรเพิ่ม แค่อย่าสลับลำดับถ้าจะย้ายบรรทัด `<script>`)

## โครงสร้างไฟล์

```
index.html

  part2.js   (~1,650 บรรทัด) — ตารางสต็อก, หมวดหมู่, ลูกค้า, ประวัติ/คืนสินค้า,

  part3.js   (~1,650 บรรทัด) — นำเข้าสินค้า Excel/ด่วน, ตั้งค่า, สำรอง/กู้คืนข้อมูล,
                                พื้นที่จัดเก็บ, เก็บบิลเก่า, สำรองข้อมูลอัตโนมัติ,

                                Audit Log, Auto Repair, Versioning, แผงควบคุม

google-apps-script/
  Code.gs    — โค้ดฝั่ง Google Sheets (วิธีติดตั้งอยู่ในคอมเมนต์หัวไฟล์)
```

## การเพิ่มโค้ดใหม่ในอนาคต

ฟังก์ชัน/ตัวแปรใหม่จะเพิ่มไว้ **ไฟล์ไหนก็ได้ใน 3 ไฟล์นี้** แล้วเรียกใช้ข้ามไฟล์ได้ทันที
ไม่ต้องเขียน import — ยกเว้นกรณีเดียวที่ต้องระวัง: ถ้าเพิ่ม **ตัวแปรระดับบนสุด** ที่ต้องถูก
ใช้งาน **ทันทีตอนโหลดหน้า** (ไม่ใช่ตอนกดปุ่ม) ต้องอยู่ไฟล์ที่โหลดก่อน ส่วนฟังก์ชันที่ถูก
เรียกตอนกดปุ่ม (ซึ่งเป็นเกือบทั้งหมดของระบบนี้) เรียงไฟล์ไหนก่อนก็ได้ไม่มีผล

ถ้าไฟล์ไหนเริ่มยาวเกิน ~2,000 บรรทัดจากการแก้ไขสะสม แนะนำให้แยกเพิ่มเป็น `part4.js`
โดยตัดที่ขอบเขต comment banner (`// ====...====`) ที่ใกล้เคียงที่สุด แล้วเพิ่ม
`<script src="js/part4.js"></script>` ต่อท้ายใน index.html

## ซิงค์ข้อมูลอัตโนมัติระหว่างหลายเครื่อง (สำหรับร้านที่สลับใช้เครื่อง ไม่ใช่ขายพร้อมกันหลายจุด)

เหมาะกับร้านที่ใช้คนเดียว/ครอบครัว สลับเปิดใช้งานคนละเครื่อง/เบราว์เซอร์ไม่พร้อมกัน (เช่น เช้าเปิดจาก
เครื่อง A บ่ายเปิดจากเครื่อง B) — **ไม่เหมาะกับการขายพร้อมกันหลายจุดจริงพร้อมกัน** (ยังไม่มีระบบกันขาย
สินค้าชิ้นสุดท้ายซ้ำระหว่าง 2 เครื่อง)

**ทำงานยังไง:**
- ทุกครั้งที่มีการเปลี่ยนแปลงข้อมูลในเครื่องนี้ (ขาย/แก้สินค้า/เปิดปิดกะ ฯลฯ) ระบบจะส่งข้อมูล
  ทั้งหมด (ทั้งฐานข้อมูล ไม่ใช่แค่สินค้า) ขึ้น Supabase ให้อัตโนมัติในเบื้องหลัง (หน่วงไว้ ~2.5 วินาที
  หลังการเปลี่ยนแปลงล่าสุด กันยิง API ถี่เกินไป)
- ทุกครั้งที่เปิดแอปขึ้นมาใหม่ (ไม่ว่าเครื่องไหน) จะมีหน้าจอ "กำลังตรวจสอบข้อมูลล่าสุด..." ขึ้นก่อน
  เสมอ ระบบจะเช็ค Supabase ว่ามีข้อมูลใหม่กว่าที่เครื่องนี้เคยรู้ไหม ถ้ามีจะดึงมาใช้แทนอัตโนมัติ ก่อน
  แสดงหน้าจอจริงให้เห็น — ถ้าร้านเปิดอยู่แล้วจากอีกเครื่อง เครื่องนี้จะเห็นสถานะเปิดอยู่ทันที
- มีป้ายสถานะที่หน้าล็อกอิน (🟢 ซิงค์แล้ว / 🔴 ออฟไลน์ / ⚪ ยังไม่เคยซิงค์) ให้เช็คง่ายๆ
- ปุ่ม **"🔄 บังคับซิงค์ตอนนี้"** ในหน้าตั้งค่า สำหรับบังคับส่งข้อมูลทันทีโดยไม่ต้องรอ (เช่น ก่อนส่งมอบ
  เครื่องให้อีกกะ)
- ถ้าออฟไลน์ (ไม่มีเน็ต) แอปยังใช้งานได้ตามปกติทุกอย่าง แค่ไม่มีการซิงค์จนกว่าจะมีเน็ตอีกครั้ง —
  ข้อมูลในเครื่องปลอดภัยเสมอไม่ว่าจะซิงค์สำเร็จหรือไม่ (localforage/IndexedDB ยังเป็นฐานข้อมูลหลัก
  ของเครื่องนั้นๆ อยู่เสมอ)

**การตั้งค่า:** ต้องรัน `pos_state_table.sql` เพิ่ม 1 ตาราง (แยกจากตาราง products/categories/...
ที่มีไว้สำหรับดูข้อมูลใน Table Editor เฉยๆ)



- `js/supabase-integration.js` — เชื่อมต่อกับโปรเจกต์ Supabase ที่ตั้งไว้แล้ว (URL + anon key ฝังอยู่ในไฟล์)
- ปุ่ม **🗄️ ซิงค์สินค้าไป Supabase** ในหน้า ⚙️ ตั้งค่า — เขียนทับตาราง `products`, `product_variants`,
  `product_fractions`, `product_categories`, `categories` ให้ตรงกับข้อมูลในเครื่อง
- ในหน้าแก้ไขสินค้า มีปุ่ม **"📤 อัปโหลดรูปจากเครื่อง (ไป Supabase)"** — อัปโหลดรูปเข้า Storage bucket
  `product-images` ทันทีแล้วเติมลิงก์ให้อัตโนมัติ ไม่ต้องหาลิงก์รูปจากที่อื่นมาวางเอง
- ตาราง SQL ที่ต้องสร้างไว้ล่วงหน้าใน Supabase (SQL Editor): `categories`, `products`,
  `product_variants`, `product_fractions`, `product_categories` (ตารางเชื่อมสินค้า-หมวดหมู่แบบ
  many-to-many) พร้อม Row Level Security และ Storage bucket `product-images` (public)



- **เพิ่มหน้าจัดการซัพพลายเออร์** (👥 จัดการซัพพลายเออร์ ในหน้ารับของเครดิต) — เดิม dropdown เลือก
  ซัพพลายเออร์ถูก hardcode ไว้แค่ 2 รายการตายตัวใน HTML เพิ่ม/แก้ไข/ลบซัพพลายเออร์จริงไม่ได้เลย
  ตอนนี้เพิ่ม/แก้ไข/ลบได้จากหน้าแอปโดยตรงแล้ว dropdown ดึงข้อมูลจริงจากฐานข้อมูลเสมอ
- **แก้ชื่อสถานะใบสั่งซื้อที่สับสน** — เดิมใช้ `'RECEIVED'` หมายถึง "จ่ายเงินแล้ว" ซึ่งอ่านแล้วเข้าใจผิด
  ว่าหมายถึง "รับของแล้ว" เปลี่ยนเป็น `'UNPAID'`/`'PAID'`/`'CANCELLED'` ให้สื่อความหมายตรงกับสิ่งที่
  มันบันทึกจริง
- **รองรับผ่อนจ่ายเจ้าหนี้บางส่วน** — เดิมต้องจ่ายเต็มจำนวนครั้งเดียวเท่านั้น ตอนนี้ระบุจำนวนเงินที่จะ
  จ่ายแต่ละครั้งได้ ระบบติดตามยอดจ่ายสะสม/คงค้างอัตโนมัติ
- **เพิ่มปุ่มยกเลิกใบสั่งซื้อ** สำหรับใบที่ยังไม่จ่ายเงิน — คืนสต็อก/ต้นทุนกลับเป็นค่าก่อนรับของให้
  อัตโนมัติ (มีระบบตรวจสอบกันพลาด จะไม่ให้ยกเลิกถ้าสต็อกล็อตนั้นถูกขาย/ปรับไปแล้วบางส่วน)
- **เพิ่มยอดสรุปเจ้าหนี้รวม** แสดงที่หัวหน้ารายการใบสั่งซื้อค้างชำระ

## ระบบใหม่ที่รวมอยู่ในไฟล์นี้แล้ว (เหมือนเวอร์ชัน ES Modules ทุกประการ)

- Database Validator / Health / Audit Log / Auto Repair / Versioning (ปุ่ม 🩺 ในหน้า
  ⚙️ ตั้งค่า)
- ปุ่มล้างข้อมูลสินค้า / รีเซ็ตระบบ (มี PIN + พิมพ์ยืนยัน + auto-backup + กันกดซ้ำ)
- ระบบนำเข้าสินค้ารองรับคอลัมน์หมวดหมู่ + ตรวจค่าติดลบ/บาร์โค้ดซ้ำ
- ระบบซิงค์ Google Sheets เต็มรูปแบบ 12 ตาราง (ดูรายละเอียดคอลัมน์ในไฟล์
  `google-apps-script/Code.gs`) — ตารางสินค้าออกแบบเป็น 3 ตารางเชื่อมกัน (แบบ
  relational) แทนการยัดทุกอย่างเป็น JSON ในเซลล์เดียว:
  - **สินค้าหลัก** — 1 แถวต่อ 1 สินค้า มีคอลัมน์ "รูปภาพ" ที่ใช้สูตร `=IMAGE()`
    แสดงภาพจริงในเซลล์ทันทีถ้ากรอกลิงก์รูปไว้ในแอป (ช่อง "URL รูปภาพสินค้า"
    ตอนแก้ไขสินค้า)
  - **ตัวเลือกสินค้า_ขนาด** — 1 แถวต่อ 1 ขนาด/รุ่น พร้อมราคา ต้นทุน สต็อก
  - **หน่วยย่อย_แบ่งขาย** — 1 แถวต่อ 1 หน่วยแบ่งขาย (เช่น "ตัดขายเมตรละ")
  
  ทั้ง 3 ตารางกรอง/เรียง/แก้ไขได้ตรงๆ ใน Sheets โดยไม่ต้องแกะ JSON เชื่อมกันด้วย
  รหัสสินค้า/รหัสตัวเลือก เหมือนฐานข้อมูลเชิงสัมพันธ์ทั่วไป

## วิธี Deploy ขึ้น Firebase Hosting

เหมือนเดิมทุกขั้นตอนที่เคยทำ แต่**ง่ายกว่าเดิม** เพราะไม่มีเรื่อง ES Modules มาเกี่ยวข้อง:

```bash
cd Smart-pos-pro-v9-plain-split
firebase init hosting     # public directory: .
firebase deploy --only hosting
```

## วิธี Deploy ขึ้น GitHub Pages

โปรเจกต์นี้เป็นไฟล์ static ล้วน (ไม่มีขั้นตอน build, ไม่ใช้ ES Modules) จึงขึ้น GitHub Pages
ได้ตรงๆ โดยไม่ต้องแก้โค้ดเพิ่ม มีไฟล์ `.nojekyll` แนบไว้แล้วเพื่อให้ GitHub เสิร์ฟไฟล์แบบ
static ตรงๆ ไม่ผ่านตัวประมวลผล Jekyll (ป้องกันปัญหากับโค้ดที่มีเครื่องหมาย `{{ }}` ในคอมเมนต์)

ขั้นตอน:

1. สร้าง repository ใหม่บน GitHub (public หรือ private ก็ได้ — repo private ใช้ Pages ได้ถ้า
   เป็นแผน GitHub Pro หรือ organization)
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น repo นั้น (`index.html` ต้องอยู่ที่ root ของ repo หรือ
   ของโฟลเดอร์ที่เลือกให้ Pages เสิร์ฟ)
3. ไปที่ repo > **Settings** > **Pages**
4. หัวข้อ **Build and deployment** > **Source** เลือก **Deploy from a branch**
5. **Branch** เลือก `main` (หรือชื่อ branch หลักของคุณ) และเลือกโฟลเดอร์ **/(root)** แล้วกด **Save**
6. รอ 1-2 นาที แล้วรีเฟรชหน้า Settings > Pages จะมีลิงก์ปรากฏ เช่น
   `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/`
7. เปิดลิงก์นั้นเพื่อใช้งานแอป — ระบบสแกนบาร์โค้ดต้องการ HTTPS ซึ่ง GitHub Pages มีให้อัตโนมัติ
   อยู่แล้ว จึงใช้กล้องสแกนได้ทันทีไม่ต้องตั้งค่าเพิ่ม

**หมายเหตุ:** ไฟล์ `firebase.json` ไม่มีผลใดๆ กับ GitHub Pages (ใช้เฉพาะตอน deploy ขึ้น Firebase
Hosting เท่านั้น) เก็บไว้ใน repo ได้เฉยๆ ไม่ต้องลบทิ้ง
