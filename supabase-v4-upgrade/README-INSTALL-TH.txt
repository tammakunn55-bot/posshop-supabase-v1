SMART POS SUPABASE V4 — CLEAN BASELINE
=====================================

แพ็กเกจนี้เป็นชุดเริ่มต้นที่รวมโครงสร้างฐานข้อมูลและฟังก์ชัน Supabase รุ่นล่าสุดไว้ใน SQL ไฟล์เดียว
ลบไฟล์ migration ระหว่างทาง ไฟล์ SQL ตรวจสอบซ้ำ และไฟล์ .reference ที่ซ้ำกับโค้ดหลักออกแล้ว

ไฟล์หลัก
--------
- SMARTPOS_V4_ONE_RUN_INSTALL.sql : SQL รวมทุกส่วน ติดตั้งครั้งเดียวสำหรับ Supabase โปรเจกต์ใหม่
- 00-failsafe.js / 00-error-overlay.js : ตัวช่วยแสดงและป้องกันข้อผิดพลาดฝั่งหน้าเว็บ
- 01-core.js / 02-sales-stock.js : โค้ดหลักของ Smart POS ที่ให้มา
- 04-supabase.js : การเชื่อมต่อ Supabase/Auth และโค้ดเดิมที่ยังใช้ร่วมกับแอป
- 04-supabase-v4-product-sync-patch.js : ซิงค์หมวดหมู่ สินค้า และรุ่นสินค้า
- 04-supabase-v4-sales-patch.js : บันทึกการขายผ่าน process_sale_atomic
- 05-legacy-pos-state-guard.js : ปิดการส่ง pos_state แบบเดิมซึ่งไม่ใช่แหล่งข้อมูลหลักของ V4
- 06-supabase-v4-customer-supplier-sync.js : ซิงค์ลูกค้าและผู้จำหน่าย
- 07-supabase-v4-stock-control.js : ปรับสต็อกผ่าน RPC ที่ตรวจสิทธิ์และบันทึกประวัติ
- 08-supabase-v4-receiving-refund.js : รับสินค้าเข้าและคืนสินค้า
- 09-supabase-v4-void-sale.js : ยกเลิกบิลและบันทึกการกลับรายการชำระเงิน
- 10-product-catalog-import-export.js : ส่งออก/นำเข้าสินค้า CSV/JSON พร้อมหลายรุ่น หน่วยย่อย หมวดหมู่ และรูปภาพ
- PRODUCT_IMPORT_TEMPLATE.csv : แม่แบบ CSV สำหรับแก้ไขใน Excel แล้วนำกลับเข้าโปรแกรม

ติดตั้งฐานข้อมูล
----------------
1. สำรองฐานข้อมูลและไฟล์โปรแกรมที่ใช้อยู่ก่อนเสมอ
2. เปิด Supabase โปรเจกต์ใหม่ที่แยกจากข้อมูลจริง แล้วเข้า SQL Editor
3. เปิด SMARTPOS_V4_ONE_RUN_INSTALL.sql แล้วรันทั้งไฟล์ครั้งเดียว
4. ไฟล์ SQL นี้รวม schema, RLS, local_id, product_fractions, VAT ของรายการคืนสินค้า,
   การรับสินค้า, การคืนสินค้า, การยกเลิกบิล, payment reversals และ RPC ขายที่รองรับราคา/หน่วยย่อยแล้ว
5. อย่ารัน SQL migration หมายเลข 08–14 เดิมแยกเพิ่มอีก เพราะถูกรวมเข้า SQL หลักแล้ว
6. เพิ่ม Supabase JS v2 CDN ในหน้าเว็บก่อนสคริปต์แอป และตั้งค่า Supabase URL กับ anon/publishable key
   ผ่านหน้าตั้งค่าของโปรแกรม ห้ามใส่ service_role key ใน browser
7. โหลดไฟล์ JavaScript ตามลำดับที่แนะนำด้านล่าง

ข้อควรทราบสำคัญ
---------------
- SQL หลักนี้ออกแบบสำหรับโปรเจกต์ Supabase ใหม่/ฐานข้อมูลทดสอบที่ว่างเปล่าเท่านั้น ไม่ใช่ migration
  สำหรับฐานข้อมูล production ที่มีข้อมูลแล้ว ห้ามรันทั้งไฟล์ทับโดยไม่วางแผนย้ายข้อมูลก่อน
- SQL ใช้ VAT แบบบวกเพิ่มจากฐานภาษี (VAT-exclusive) หากร้านตั้งราคาสินค้ารวม VAT ต้องปรับกติกาภาษีก่อนใช้จริง
- ราคาขายหน่วยปกติอ้างอิง product_variants.selling_price ส่วนหน่วยแบ่งขายอ้างอิง product_fractions.fraction_price
  และ multiplier คือจำนวนหน่วยสต็อกฐานที่ใช้ต่อหน่วยขายย่อยหนึ่งหน่วย
- การซิงค์ข้อมูลสินค้าจะไม่เขียนทับ stock จากข้อมูล local; ตั้งสต็อกเริ่มต้นผ่านฟังก์ชันปรับสต็อกที่มีสิทธิ์
- การคืนสินค้าสามารถเพิ่มสต็อกตามตัวเลือกที่ส่งให้ RPC; การยกเลิกบิลรับเฉพาะบิล completed ที่ยังไม่มีคืนสินค้า
- payment_reversals เป็นบันทึกบัญชี ไม่ได้คืนเงินจริงให้ธนาคาร/เครื่องรับบัตรโดยอัตโนมัติ
- ฟังก์ชันสำคัญถูกจำกัดด้วย role และ RLS แต่ต้องทดสอบ role, multi-store isolation, สต็อกไม่พอ,
  retry/idempotency, VAT, ส่วนลด, หน่วยแบ่งขาย, คืนสินค้า และยกเลิกบิลบน staging ก่อนใช้งานจริง
- ตรวจไวยากรณ์ JavaScript และโครงสร้างไฟล์แล้ว แต่ยังไม่ได้รัน SQL กับ Supabase จริงในโปรเจกต์ของผู้ใช้


นำเข้า/ส่งออกสินค้า
-------------------
- เปิดปุ่ม “นำเข้า/ส่งออกสินค้า” เพื่อส่งออก JSON ครบชุด หรือ CSV ที่เปิดแก้ใน Excel ได้
- CSV รุ่น 2 มีข้อมูลชื่อ/รหัสสินค้า แบรนด์ รายละเอียด หมวดหมู่ กลุ่ม รูปภาพ รุ่น/ขนาด SKU บาร์โค้ด หน่วย ทุนปัจจุบัน/ทุนล่าสุด ราคาขาย สต็อกขั้นต่ำ เปอร์เซ็นต์กำไรขั้นต่ำ สถานะรุ่น และหน่วยแบ่งขาย
- CSV หนึ่งแถวแทนรุ่นสินค้า หรือหน่วยแบ่งขายหนึ่งรายการ; เมื่อสินค้าเดียวมีหลายรุ่น/หน่วยแบ่งขาย ให้ใช้ product_id เดียวกันและ variant_id/fraction_id แยกกัน
- JSON เก็บโครงสร้างสินค้าครบกว่า CSV และรองรับฝังไฟล์รูปใน JSON; ใช้เมื่อต้องย้ายไปคนละร้าน/โปรเจกต์
- เมื่อใช้ CSV เลือกรูปหลายไฟล์ได้ โดยตั้งชื่อรูปให้ตรงกับ image_filename, product_id, variant_id, barcode หรือ SKU เช่น 8850000000000.jpg
- ก่อนนำเข้า ระบบตรวจจำนวนคอลัมน์ ชื่อสินค้า ตัวเลขติดลบ/ไม่ใช่ตัวเลข ตัวคูณหน่วยย่อย รหัสซ้ำ บาร์โค้ดซ้ำ และ SKU ซ้ำ
- หากมีข้อผิดพลาด สามารถเลือก “นำเข้าเฉพาะสินค้าที่ผ่านการตรวจสอบ” เพื่อข้ามทั้งกลุ่มสินค้าที่ผิด และกด “ดาวน์โหลดรายงานข้อผิดพลาด” เพื่อรับ CSV ที่มีเลขแถวและเหตุผล จากนั้นแก้ไฟล์แล้วนำเข้าใหม่
- การนำเข้าเป็นแบบ merge ไม่ลบสินค้าอื่นอัตโนมัติ จับคู่ด้วย product ID ก่อน แล้วใช้บาร์โค้ด/SKU ช่วยจับคู่เมื่อจำเป็น; หมวดหมู่ที่อยู่ใน JSON จะถูกนำเข้าโดยจับคู่ชื่อหมวดหมู่
- โดยค่าเริ่มต้นไม่เขียนทับสต็อก; หากเลือกนำเข้าสต็อก ระบบใช้ set_variant_stock RPC ที่จำกัดสิทธิ์เจ้าของร้าน/ผู้จัดการและบันทึก stock movement
- การนำเข้าจะเก็บข้อมูลในเครื่องเป็นธุรกรรมเดียว หากเกิดข้อผิดพลาดระหว่างอัปโหลดรูปจะย้อนการเปลี่ยนแปลงในเครื่อง แต่การซิงค์คลาวด์อาจสำเร็จเพียงบางส่วนได้ จึงต้องตรวจข้อความผลลัพธ์และซิงค์ซ้ำหลังแก้ปัญหา
- หากต้องการซิงค์คลาวด์ ต้องเข้าสู่ระบบ Supabase และติดตั้ง SQL หลักให้ครบก่อน; รูปต้องเป็น JPG/PNG/WebP ไม่เกิน 5 MB หลังการบีบอัด
- CSV เก็บ URL/Storage path ได้ แต่ signed URL อาจหมดอายุ จึงควรใช้ JSON แบบฝังรูปเมื่อย้ายไปคนละร้าน; ฝังรูปได้เฉพาะรูปที่เบราว์เซอร์อ่านได้
- สำหรับไฟล์ขนาดใหญ่ ให้เริ่มด้วย CSV แบ่งเป็นชุดตามหมวดหมู่/ผู้ผลิต และสำรองข้อมูลก่อนนำเข้าเสมอ

ทดสอบหลังติดตั้ง
-----------------
1. สร้างร้านและสมาชิกที่มีสิทธิ์เหมาะสม แล้วซิงค์สินค้า/รุ่นสินค้า
2. ตั้งสต็อกเริ่มต้นผ่านฟังก์ชันปรับสต็อกที่มีสิทธิ์
3. ขายสินค้าปกติและหน่วยแบ่งขาย ตรวจ sales, sale_items, payments และ stock_movements
4. ทดสอบขายซ้ำด้วย idempotency key เดิม ต้องไม่ตัดสต็อกซ้ำ
5. รับสินค้าเข้า ตรวจ receiving_documents, receiving_items และ stock_movements
6. คืนสินค้าบางส่วนและคืนครบ ตรวจ refunds/refund_items/VAT/stock
7. ยกเลิกบิลทดสอบที่ไม่มีคืนสินค้า ตรวจ sale_voids, payment_reversals และ stock_movements
